## Why
Keep a pack of projects so that the human and any agent (Claude Code, Codex, others) know what is where, why, and what comes next, and can hand a project from one agent or model to another without digging through the code. Grew out of using drift, without its TUI editor and with the meta tied to reality.

## What it is
A Go CLI without dependencies: `cmd/omut` (commands), `internal/meta` (parsing meta files), `internal/check` (rules), `internal/scaffold` (init/start/zero/kill), `templates/` (embedded, usable by hand). The intent is `docs/spec-v0.md`, the neighbours are `docs/research/competitors.md`.

## Where it lives
GitHub: github.com/metravod/omut (public, 2026-11-01). CI: Linux tests on every push (.github/workflows/ci.yml); this repo's own meta checked with `--fail-on warn` on push and weekly (omut.yml, the badge in README.md); macOS tests by hand and before every release (macos.yml, called by release.yml). Releases via goreleaser on a v* tag (.github/workflows/release.yml; the HOMEBREW_TAP_TOKEN secret is a fine-grained token with Contents: write on metravod/homebrew-tap only); the Homebrew cask goes to github.com/metravod/homebrew-tap (`brew install metravod/tap/omut`). Without brew: `install.sh` in the repo root (curl or wget, checksums from the release), `mise use -g github:metravod/omut`, `go install`; CI's install job tries all but go install on Linux against the latest release. Nothing runs anywhere. This copy's machine (the checkout, the pack, the installed binary, hooks): `local/instance.md`, not in git.
