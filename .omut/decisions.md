# Decisions

- D1 [accepted 2026-10-31] Agent- and provider-agnostic: state in files, entry through AGENTS.md and the CLI, hooks only as adapters. Rejected: relying on Claude Code mechanisms (auto memory, Tasks, ~/.claude/projects), since people mix agents and hand work between them
- D2 [accepted 2026-10-31] One pack root directory; the lead is any agent started in the root, not a separate program
- D3 [accepted 2026-10-31] Where to keep it, what to commit and how to sync is the user's call; the system only shapes the meta
- D4 [accepted 2026-10-31] The pack view is assembled on read, there is no registry. Rejected: a registry like drift's, which went stale (active projects missing, empty ones listed)
- D5 [accepted 2026-11-01] Project meta: brief / decisions / threads / log in a hidden `.omut/`. Agents get exact paths from the AGENTS.md block, so hiding costs nothing; listings stay clean. Rejected: a visible `lead/`; threads with an `idea` status
- D6 [accepted 2026-10-31] A decision registry instead of owning ADRs: a line with a status and a link to the project's ADR, or a short reason right in the line
- D7 [accepted 2026-10-31] Commands: init, start, freeze, thaw, kill, check, zero; no commands that write meta. kill writes a tombstone instead of scrubbing mentions
- D8 [accepted 2026-11-01] Go, one static binary. Rejected: Python and Node, which pull in a runtime and contradict "no runtime of its own"
- D9 [accepted 2026-11-01] One active writer of the meta; parallel work only with an explicit split of responsibility
- D10 [accepted 2026-11-01] Templates, CLI messages and docs in English; the meta's text is written in whatever language the project's people use, headings and labels stay fixed for `check`
- D11 [accepted 2026-11-03] omut doesn't run checks against reality; it remembers them. Each `- ` line of "Where it lives" (brief and `local/instance.md`) and of "Access" is a claim that may carry ` · how: <command or place to look> · seen YYYY-MM-DD`; an agent runs `how` under its own permissions and updates `seen`. `check` warns about claims not seen for 30 days (`unseen`) and counts those without `how` (`unchecked`); `hook start` offers up to two claims not seen for 7 days, never-seen first (the audit a little every session); the rules list where footprints hide, for the agent to search. Why: the human's call, "omut stores where and how to look, the agent executes"; it keeps the CLI a CLI (spec §2.3), needs no trust gate, no per-OS code, and reaches whatever an agent reaches, prod and non-code projects included. Rejected: probes run by `check` (a shell in a markdown file that agents write), a trust gate like direnv, `omut observe` scanning the machine, public probes in omut (a project's CI can run its own). Cost: the truth rests on the agent; a log line saying what was seen is the evidence → docs/research/reality-check.md
- D12 [accepted 2026-11-02] A project carries its own rules: `.omut/README.md`, a tool file `zero` keeps current, with a reading guide for visitors and the full rules for those who keep the meta; the pack's `conventions.md` is retired. A pack is optional: `start`, `zero`, `freeze`, `thaw`, `check` work on a single repository. Why: a project is cloned and published without its pack, and the old link `../.omut/conventions.md` led nowhere; GitHub renders the README when someone opens `.omut/`. Rejected: a link to the spec online (agents work offline and don't fetch), keeping both copies (they drift)
- D13 [accepted 2026-11-02] `omut hook start|commit`: one read-only command that agents' and git's hooks call, with per-agent recipes in docs/hooks.md as thin adapters (D1); silent outside any meta, so it can be installed globally. The end of a session is the git commit, not the agent's stop hook: Claude Code, Codex and Cursor fire it after every turn, so a reminder there nags after every answer; uncommitted work is caught at the next start through `stale-brief`. Without git, the signal is the next start ("unrecorded work") and the prose ties recording to "before telling the human it's done". Extends D7. Rejected: a stop-hook reminder; `omut hook install` writing agents' configs (they are the user's files)
- D14 [accepted 2026-11-03] A project with ADRs keeps one registry, not two: with `adr:` in the brief, the ADRs are the registry for the decisions they record, `decisions.md` holds only decisions without an ADR, and `check` reads statuses from the ADR files (frontmatter, a `Status:` line or a `## Status` section; `proposed`/`draft` listed like `open`, stare-decisis `Firmness: tentative` like `doubted`, no status counts as decided). Replaces the `adr-ahead` rule. Why: zymi-core has 46 ADRs and its mirror registry already disagreed with them (ADR-0033); copying every ADR is friction when adopting a repository that has them. Rejected: keeping both and warning on mismatch (the double bookkeeping stays); parsing ADR formats beyond the status line. A mirror registry that exists may stay. Decision of the human → docs/spec-v0.md
- D15 [accepted 2026-11-03] Two layers of meta. The project layer (everything in `.omut/` but `local/`) goes into git and is for continuity: why, what, decisions, the work, the public footprint. The instance layer, `.omut/local/` (`instance.md`: Where it lives, Access, Runbook; and its own `log.md`), is the memory of one copy, like `.env`: its machine, servers, where secrets are kept, deploy and moves. Test for a fact: would a stranger who clones need it, and is it true for them? `.omut/.gitignore` (a tool file) keeps `local/` out of git without touching the project's `.gitignore`; `check` adds `leak` (home paths, IPs, `~/` in the brief's "Where it lives"), `local-not-ignored`, `local-in-git`; `hook start` gives both layers; `kill` refuses over a filled instance layer. Why: pack D1 hid meta because of prod and strategy, which is this split done by hand; the 2026-11-02 move broke only instance facts; most of D11 is about the instance layer, where probes are the user's own, not a repository's code. Rejected: the layer outside the checkout (`~/.omut/<project>/`, keyed by path, which broke on the move); the project's own `.gitignore` (start doesn't touch project files). Not now: decisions of an instance, backing the layer up. The human's idea → docs/research/reality-check.md
- D16 [accepted 2026-11-03] One tool, one format, no modes for personal, team or open-source use: any agent must read any repository's meta without knowing how it was set up. Visibility is one bit read from git, never stored: `start --private` keeps the whole meta out of git through `.git/info/exclude` and points Claude Code at it through `CLAUDE.local.md` (Codex has no additive local file: the hook or `~/.codex/AGENTS.md`), so omut can be tried on a repository that is not yours; sharing later is removing the exclude lines, `zero`, a commit. Teams get rules, not a mode: one keeper per thread, decisions name who accepted them, `log.md merge=union` in `.omut/.gitattributes`. Rejected: `--mode personal|team|oss` (a matrix of formats and rules), the private pointer in `AGENTS.override.md` (it replaces the repository's `AGENTS.md` for Codex), union merge for `decisions.md` (a changed status kept twice) → docs/spec-v0.md
- D17 [accepted 2026-11-04] One memory per clone. In a linked git worktree, committed meta follows the branch like any tracked file; `.omut/local/` and all of private meta stay in the main checkout, and every command finds them from a worktree. Why: a worktree's own copy goes when the worktree goes and drifts while it lives; `local/` describes a machine, not a branch; Claude Code's own auto memory is shared across worktrees in the same way. Found in a real session: in a worktree of a private project `hook start` was silent, so the agent got no context. Cost: parallel agents write the same files, so "one keeper per thread" matters more. Rejected: `start --private` in each worktree (copies that drift). Decision of the human → docs/spec-v0.md
- D18 [accepted 2026-11-04] Agents' memory belongs to the human, and omut doesn't change how it is used by default. When adopting, the agent moves what only its memory holds into the meta and asks once whether memory should from then on keep only the human's preferences and what they asked to keep out of the meta; a yes is one line in the file with the omut block, outside the markers. Why: a real adoption wrote one result to five places, and the rule said what to move but not what happens to the memory; the human's call that this is not omut's to impose. Rejected: a rule for all (it reaches into the user's agent); a second block commented out in AGENTS.md, the human's first idea (`zero` rewrites what is between the markers, Claude Code strips HTML comments so its agent couldn't see the option to ask, Codex reads them as text) → templates/project/omut/README.md
