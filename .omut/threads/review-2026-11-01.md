# Independent review of v0
**Goal:** turn the findings of the first outside review into fixes and decisions.
**Where we got:** the review is done (spec, competitors, all code, templates, a scratch pack, the live meta in data-agent). Findings 1, 2, 5 and 6 are fixed (2026-11-02); the rest are goals.
**Verified:** findings 1, 2, 5, 6: a test each, red on the old code and green on the new; `check` on `~/oss_projects` has no false warnings.
**Not verified:** `stale-brief` when the project is a subdirectory of a git repo (it needs `.git` in the project itself and walks mtimes otherwise); speed on a large pack (two git calls per project).
**Open:** D11 (probes); findings 7–12 from the first real pack (2026-11-02) are not triaged yet; whether hook recipes stay "optional" in the spec or become the recommended path (D1 allows adapters).
**Next step:** hooks (finding 4) for every agent, not only Claude Code; triage 7–13.

## Findings
1. **Fixed 2026-11-02 (`EvalSymlinks` before the walk).** **Bug: `stale-brief` is blind inside a symlinked project.** `newestChange` (`internal/check/check.go`) calls `filepath.WalkDir` on the project dir; when the dir is a symlink, WalkDir doesn't descend, so only the link's own mtime and the last commit date count. Repro: a git project outside the pack, linked into it, `updated` older than an edit to a tracked file, no `stale-brief`. Fix: `filepath.EvalSymlinks(dir)` before the walk. The brief's "check on a pack of symlinked real projects" was therefore weaker than it looked.
2. **Fixed 2026-11-02: as proposed, and a commit that touches only `.omut/` doesn't count either.** **`stale-brief` false positive after a fresh clone.** A clone sets every mtime to the clone date, so a colleague gets `stale-brief` on day one, which is exactly the handoff case. Idea: in a git repo use the last commit date plus the mtimes of files in `git status --porcelain`; walk all mtimes only without git.
3. **The differentiator is declared, not mechanical.** `check` checks shape and mtime freshness; checking "Where it lives" against reality is prose in `LEAD.md` that any neighbour can copy. Idea: optional machine-checkable lines in "Where it lives" (`probe: ssh <host> systemctl is-active <unit>`, a URL, a cron line) run by `check --probe`. Fleet tools (fleet-recon, fleetwatch) are natural sources. → D11.
4. **Rituals rest on the agent's discipline; session end is the weakest one.** No agent gets a reliable "session is over" signal, so log and "Now" will rot. Ship hook recipes early (`compatibility/<agent>.md`, spec §10): `omut check <project>` at session start, a log/"Now" reminder on stop. Not Claude Code only (D1): the agent-neutral signals are git (a pre-commit hook with `omut check`) and CI; per-agent hooks are thin adapters calling the same command.
5. **Fixed 2026-11-02: without git `kill` needs `--force`.** **`kill` on a project without git is a bare `rm -rf` behind `--yes`.** The command is meant for agents. Idea: without git require `--force`, or move the directory to the trash.
6. **Fixed 2026-11-02.** **False `pointer` warning when Claude gets AGENTS.md through `CLAUDE.local.md`.** Found 2026-11-02 while adopting wimt_agent into the `~/oss_projects` pack: the tracked `CLAUDE.md` has the project's ADR rules, the gitignored `CLAUDE.local.md` holds `@AGENTS.md`, and `check` still warns. Claude Code reads `CLAUDE.local.md` too, so the rule should accept an `@AGENTS.md` line in either file.

## Findings from the first real pack (2026-11-02, adopting 5 projects into `~/oss_projects`)
7. **No migration path from drift.** omut grew out of drift, so this is the path every early user takes, and it isn't described. The conventions say "don't copy an old journal; link to it", but when the journal is deleted there is nothing to link to. Improvised: a script that converts `.drift/project.json` (+ `archive.md`) into `.omut/log-archive/drift.md`; the conventions only know `log-archive/<year>.md`. Unverified whether `check` reads `log-archive/` at all. Idea: a documented recipe or `omut start --from-drift`.
8. **Double bookkeeping with ADRs.** zymi-core has 46 ADRs; one registry line per decision means a copy of `adr/` that drifts from it (ADR-0033 already says "Proposed" while shipped, now fixable in two places). Idea: with `adr:` in the brief, `check` reads statuses from the ADR files, and `decisions.md` keeps only decisions without an ADR.
9. **Local-only meta isn't supported by the CLI.** `start` writes `AGENTS.md` and the `CLAUDE.md` symlink but knows nothing about ignoring them; the pack decided meta stays local (pack D1), so `.gitignore` was edited by hand in 5 repos, leaving commits that exist only because of omut. Better: `.git/info/exclude` is local and needs no commit. Idea: `omut start --local` writes `.omut/`, `AGENTS.md`, `CLAUDE.md` there.
10. **The format has no room for incomplete sources.** Decisions recovered from agent memory have no date, but the line needs one (a proxy date plus a note was used). A log entry with a date range (`2026-04-02…2026-10-07`) fails `shape`. Unclear where the `(from session)` marker goes: author field or text. Idea: an explicit unknown date (`????-??-??` or `[accepted ?]`) and one documented place for the marker.
11. **Noise from projects nobody works on.** zymi-core is in quiet maintenance, but `check` will keep reporting its `open` ADR-0043 and `doubted` D55 as info on every overview. Open question, not a bug: should `frozen` (or some "maintenance" state) mute these?
12. **No relocation ritual.** The meta survived `mv` intact (supports D1); everything that broke was outside: skill symlinks, permission rules in settings, absolute paths in a `.venv`, path-keyed agent memory dirs. "Where it lives" helped find them, but LEAD.md has "adopting" and no "relocating", so the checklist was assembled on the fly. Overlaps with D11: a dangling symlink is easy to probe.
13. **`kill` doesn't see gitignored files.** A clean, pushed repo passes the guard, but ignored files (`.env`, local data, and meta kept local-only as in pack D1) exist nowhere else and go with it. Idea: list ignored files outside the usual caches in the guard, or at least name a gitignored `.omut/`.
